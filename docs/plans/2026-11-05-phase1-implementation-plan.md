## Phase 1 goal and exit
`docker compose` core services come up healthy; ONE synthetic fixture document flows fixture-portal → drop dir → raw store → 3 extractors → bronze → silver → classifier → `semantic_loans_v1` → snapshot → API → KrakenD → a keyboard-accessible map pin (with hover tooltip) and table row. Integration test green. **Fixtures only; no live portal contact** (ToS review gates any live scrape). Classifier = §9 placeholder (every loan `is_bridge_loan=true`, `bridge_score=100`, `classifier_version=placeholder-all-true`).
**Out of Phase 1 (explicit deferrals):** live Mattapoisett ingest, Rye/Madison, Lambda/Mangum, OpenTofu/cloud, pin clustering (Phase 5), label-based accuracy reports.

## Conventions
- Python 3.12 + uv workspace (one `pyproject.toml` per package: `backend/{common,api,ingest,fetcher}`; root `uv.lock` owned by WU1; later units add deps to their own package and regenerate the lock **serialized in merge order**). Java 17 for Spark. Pins recorded in `docs/adr/0002-version-pins.md` (Spark, Iceberg, Lakekeeper, DuckDB, Postgres, KrakenD, Node).
- Frontend: Vite + React + TS, Vitest, Playwright, axe, openapi-typescript.
- **Compose layout:** `deploy/docker/compose.yaml` (WU3) uses `include:` (each entry `required: false`, Compose ≥ 2.20, so WU3's own `up` works before later fragments exist) for per-unit fragments owned by their unit; api, krakend and web services join the `core` profile: `compose.fetcher.yaml` (WU4), `compose.extractors.yaml` (WU5a), `compose.ingest.yaml` (WU5b), `compose.api.yaml` (WU7), `compose.gateway.yaml` (WU8), `compose.web.yaml` (WU9). Likewise Makefile fragments `make/<unit>.mk` included by the root Makefile (WU1).
- **Networks:** `core` bridge (minio, postgres, lakekeeper, api, krakend, web) with ports published only to 127.0.0.1; `fetch` internal network with no route to core; extractors use `--network none`. One-shot jobs (fetcher, extractors, loaders) are run via `docker compose run --rm`, not part of `up -d` health. Cross-network hand-off uses host-mounted dirs (`data/drop`, `data/extract-in`, `data/extract-out`), never a docker socket.
- TDD: each unit's tests are committed before implementation (verified in review by commit order). Commits per unit; never `--no-verify`.
- Coverage gates: 80% on backend/common + backend/api; 95% branch on `unify` and `classify`.
- Logging: structured logs with a redaction filter (WU7 test: no borrower names in any log line).

### WU2 — Shared models, normalizers, classifier, fixtures, fixture snapshot
- **Scope:** `backend/common/{models,normalize,signals,classify,logging}.py`, `config/classifier.yaml` (`classifier_version: placeholder-all-true`, versioned signal weights), `tests/fixtures/` generator (Faker, fixed seed): synthetic PDFs (mortgage, deed, discharge, scanned-image, multi-instrument, corrupt, oversize), hand-written expected-instrument **truth** JSON (from generator ground truth), recorded Census responses (match/low_match/no_match), a **fixture snapshot generator** producing list Parquet + borrower detail Parquet + `manifest.json` (single-fixture and a 5k-row synthetic variant), local TopoJSON for Mattapoisett (public-domain).
- **DoD:** (1) models validate good / reject bad fixtures; (2) normalizers table-tested incl. missing/ambiguous dates and currency formats; (3) `classify_loan` returns `is_bridge_loan=true, bridge_score=100, classifier_version` for ANY input incl. all-unevaluable signals, swappable via config; (4) signals (`purchase_then_mortgage_90d`, `second_lien`, `short_term`, `private_lender`, `no_discharge`, `keyword`) computed and stored; unevaluable when data absent; (5) fixtures contain no real PII (denylist test); (6) snapshot generator output validates against models; 5k variant generated deterministically; (7) log filter redacts borrower names (unit test); (8) coverage gates met.
- **Deps:** WU1. (Extractor golden outputs are NOT here; they belong to WU5a.)

### WU3 — Compose core: MinIO, Postgres, Lakekeeper
- **Scope:** `deploy/docker/compose.yaml` (ADR-0002 confirms the pinned Compose supports `required: false` on `include`; otherwise make assembles the `-f` list or WU3 generates stub fragments), services: minio (generated creds from `.env`, SSE + block-public-access policy on buckets), postgres, `lakekeeper-migrate` job, lakekeeper, `bootstrap` job (create warehouse pointing at MinIO path-style S3, create buckets/namespace), healthchecks, `core` network, 127.0.0.1 publishes, `make/stack.mk`, `scripts/maintenance/expire_snapshots.py` (Iceberg snapshot expiry/compaction).
- **DoD:** (1) `docker compose --profile core up -d` → minio, postgres, lakekeeper healthy; bootstrap job exits 0; (2) pytest (host-side, via published 127.0.0.1 ports) creates an Iceberg namespace+table through the catalog with pyiceberg and reads it back via DuckDB `iceberg` extension using path-style S3 config and an explicit client-side `s3.endpoint` override (warehouse metadata carries the internal `minio:9000`, which does not resolve on the host); the pinned Lakekeeper's credential mode (vended vs remote-signing) is confirmed and recorded in ADR-0002; the pinned DuckDB version is one that supports REST-catalog attach (recorded in ADR-0002); (3) no service published on 0.0.0.0 (test parses `docker compose config`); (4) no default creds (`minioadmin` absent); (5) bucket public access blocked and SSE enabled (test); (6) expiry/compaction script tested on a table with 3 snapshots.
- **Deps:** WU1.

### WU4 — Fetcher, fake portal, drop dir, raw-ingest
- **Scope:** `backend/fetcher/{adapter,obscura,playwright,allowlist,manifest,raw_ingest}.py`, `tests/fakeportal/` (HTTP server: PDFs, CAPTCHA, timeout, 429), `deploy/docker/compose.fetcher.yaml` (fetcher image with Playwright browsers baked in; `fetch` internal network), `docs/adr/0003-obscura-spike.md`, `make/fetcher.mk`.
- **Obscura:** Obscura binary pinned in the fetcher image, or documented stub per ADR-0003. The allow-list has a test-only override (explicit config flag, refused outside test mode, with its own test) so the fake portal on a private container IP does not conflict with the block-private-IP tests. ADR-0003 notes that Phase 2 live fetching needs an egress proxy with a domain allow-list (the `fetch` network is `internal: true`).
- **Hand-off design:** fetcher writes `<sha256>.pdf` + manifest-row JSON to `data/drop/` (host dir, no MinIO route). A separate non-isolated `raw-ingest` step uploads drop files to MinIO (content-addressed, duplicate = no-op) and writes manifest rows.
- **DoD:** (1) `Fetcher` interface; Playwright adapter passes against fake portal; Obscura adapter passes OR is a documented stub — the spike is **time-boxed to 1 day** and either outcome (working or stub + ADR) passes this item; (2) allow-list: https-only + domain list, blocks loopback/private/link-local/metadata IPs, revalidates every redirect (parametrized incl. redirect-to-internal); portal host injected by config (tests use fake host); (3) fetcher container isolation test asserts no route to minio, lakekeeper, metadata IP; (4) dedupe test runs at the raw-ingest step (same sha256 twice → one object, one manifest row); (5) CAPTCHA/timeout/429 produce manifest rows with `gap_reason` ∈ {paid, blocked, failed}, no crash.
- **Deps:** WU2, WU3.

### WU5a — Extractor images and sandbox

- **Invocation:** Make/host driver runs each extractor container with input and output volumes; no docker socket; Spark is not involved here.
- **DoD:** (1) each extractor output matches its golden under **tolerance-based comparison** (normalized text similarity ≥ threshold + field-level match on key fields), versions/models pinned; (2) containers run with `--network none` and offline model env and still succeed (proves nothing lazily downloads); (3) container cannot write outside its output path and cannot resolve DNS (tests); (4) pre-validation rejects corrupt/oversize/non-PDF input; (5) scanned fixture follows documented OCR rule or is flagged `needs_ocr`; (6) AGPL ADR committed; (7) image size and build time recorded.

### WU8 — KrakenD gateway
- **Scope:** `gateway/krakend.json`, `deploy/docker/compose.gateway.yaml`, `docs/adr/0005-gateway-auth.md`, `make/gateway.mk`.
- **First task (time-boxed spike, recorded in ADR-0005):** prove how a `Retry-After` header can be produced on gateway-generated 429s (CE Lua proxy script, custom plugin, or a thin header-adding layer). The router-level `qos/ratelimit` 429 is generated before the proxy layer, so martian response modifiers may not apply.
- **Auth mechanism (decided; supersedes "API key" wording):** KrakenD CE validates a per-key-id static **HS256 JWT** (`auth/validator`); `kid`/`sub` is forwarded as `X-Key-Id`; gateway injects the shared-secret header to the backend. Rate limiting via CE `qos/ratelimit`; the spike covers BOTH header and JSON body (router-level 429 may emit an empty/plain body); fallback named in ADR-0005: a thin header+body-adding proxy in front of KrakenD or the proxy-level limiter; the 429 body is JSON with `code` and `retry_after_seconds`; the `Retry-After` header is added only if the spike proves a working mechanism; gateway-generated errors are JSON with a `code` (not required to be full problem+json); backend problem+json is passed through.
- **DoD:** (1) request without valid JWT → 401 JSON with `code`; (2) direct-to-backend without shared secret → rejected; (3) CORS rejects unlisted origin; (4) rate limit → 429 with JSON body `code` + `retry_after_seconds` (and `Retry-After` header if the spike proved it); stricter limit on `/loans/{id}`; (5) problem+json from backend passes through untouched; (6) contract test validates gateway responses against `openapi.json`; (7) only the gateway is published (127.0.0.1); (8) healthcheck passes.
- **Deps:** WU7.
